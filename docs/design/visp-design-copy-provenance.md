# 复制溯源层设计（选区复制输出原始文本）

## 1. 目标

**一句话**：为对话区每一行渲染结果建立"来源"信息，使鼠标选区复制输出**原始文本**（assistant 消息为原始 Markdown），而不是屏幕字符网格。

详细目标：

| 编号 | 目标 | 说明 |
|------|------|------|
| G1 | 折行不再被复制成换行 | 选区跨越若干**软折行**（宽度不够产生的折行）时，复制结果应还原为同一逻辑行 |
| G2 | assistant 消息复制出原始 Markdown | 选区落在 assistant 消息内，输出 `ChatLine.content` 中对应行的**原文**，保留 `#`、`**`、代码围栏、表格 `|` 等语法 |
| G3 | 视觉零回归 | 屏幕渲染输出与改造前逐字节一致，不做任何折行/宽度行为的调整 |
| G4 | 按选区、可跨消息 | 支持任意连续行区间，允许跨越 user / assistant / tool / 流式等不同区域 |
| G5 | 失败可降级 | 归因失败时退回当前行为（屏幕文本），不崩溃、不静默给出错误结果 |

非目标（见第 8 节）：表格/引用块/工具块的精确归因、行内列级精确裁剪、把渲染结果反向解析为 Markdown。

## 2. 现状与根因

### 2.1 复制链路现状

| 阶段 | 位置 | 行为 |
|------|------|------|
| 触发 | `event.rs:806` | 鼠标拖拽中持续更新 `text_selection.end`（坐标为 `(column, 屏幕 row + scroll_y)`） |
| 触发 | `event.rs:813` | 左键抬起且 `start != end` → 置 `pending_copy = true` |
| 提取 | `ui.rs:435` | 同帧渲染末尾调用 `extract_selected_text(...)`，**传入 ratatui `Buffer`** |
| 提取 | `selection.rs:196` | 逐 buffer 行读 `cell.symbol()`，仅做 `trim_end()`，然后 **`join("\n")`** |
| 剪贴板 | `event.rs:307` | `terminal.draw()` 之后取走 `pending_copy_text`，写系统剪贴板（pbcopy / wl-copy / xclip / OSC 52） |

### 2.2 两个症状，同一根因

**根因：复制路径的输入是"渲染后的屏幕字符网格"（`Buffer`），它已经丢失了源文本结构。**

| 症状 | 机制 |
|------|------|
| 问题①：折行 → 断行 | Buffer 每行都是折行产物：Markdown 内部按词折行（`app.rs:1090` 传入 `inner_w`）、代码块 `wrap_styled_line` 按字符折行（`app.rs:199`）、纯文本 `wrap_text` + `pad_to_width`（`app.rs:1271`/`app.rs:1330`）。逐行 `join("\n")` 无法区分"作者的硬换行"与"宽度不足的软折行" |
| 问题②：复制出渲染结果 | Buffer 中 Markdown 语法已被剥离（`**x**` → 样式、`#` → 普通文本、围栏 → 高亮行）。而**原文从未丢失**，一直保存在 `ChatLine.content`（`app.rs:315`），复制路径从不读取它 |

补充事实：只有 `LineType::Assistant` 走 Markdown 渲染（`app.rs:1084`）；其余走 `wrap_text`、`tool_ui` 渲染器或独立渲染函数。

### 2.3 支撑方案的关键事实（已核实）

| 编号 | 事实 | 出处 |
|------|------|------|
| F1 | `ChatLine.content` 保存原始 Markdown；统计行由 `split_assistant_footer`（`app.rs:1050`）从正文剥离，内容为 `\n\n[...]` | `app.rs:315`、`app.rs:1050` |
| F2 | 解析器**不做段落 reflow**：段落的每个源行单独存入 `Paragraph(Vec<String>)`，渲染时逐行独立折行 | `ratatui-markdown` parser / `render.rs:297` |
| F3 | 列表的"是否有后继兄弟"前瞻（`find_list_context`）只影响树枝字符与缩进，**不影响行数**；且未配置 hooks 时该结果未被使用 | `render.rs:588`、`render.rs:469` |
| F4 | 每个块的渲染分支都是**自包含**的（不读取前后块）。唯一跨块读取是 F3 | `render.rs` 各分支 |
| F5 | `MarkdownBlock` **不携带任何源文本位置信息**（无行号、无字节偏移） | `types.rs:2-37` |
| F6 | 代码块已通过 `\x00CODEBLOCK_{n}\x00` 标记在解析前被替换，`process_code_blocks` 知道每个围栏在源文本中的精确位置 | `app.rs:169` |

F2 + F3 + F4 合起来推出核心可行性结论：

> **一个块（乃至段落中的一个源行）单独渲染所得行数，与它在完整文档中渲染所得行数完全相同。**

> **一个源行最多影响一段连续的渲染行，软折行永远不会跨源行。**

## 3. 总体设计

在现有三层之上，加一层"溯源"，复制路径改为"按来源重建文本"。

```
Layer A  源文本层（已存在，零成本）
  ChatLine.content / streaming_text        ← 原始 Markdown、原始纯文本

Layer B  渲染层（已存在，完全不变）
  MessageCache.lines                       ← 屏幕行，视觉唯一真相

Layer C  溯源层（新增，按需构建）
  Vec<RowOrigin>，与 lines 一一对应        ← 每行渲染结果"来自哪个源行"

复制路径：
  旧：Buffer 行 → trim_end → join("\n")
  新：选中行 → 查溯源 → 输出源行原文
```

**核心不变式**：`origins.len() == lines.len()`，且 `origins[i]` 描述的就是 `lines[i]` 的来源。任何时刻两者不一致都视为构建失败，整体降级。

**关键简化**：溯源只需要回答"这一渲染行来自第几个源行"，**不需要区分硬换行/软折行**——因为复制时读的是源行原文，源行自带换行结构；同一源行折出的多个渲染行天然合并输出一次。

## 4. 模块划分

| 模块 | 位置 | 职责 |
|------|------|------|
| 溯源类型 | 新模块 `provenance.rs` | `RowOrigin`、`SourceRef`、`RowOriginSet` |
| 源行扫描与块对齐 | `provenance.rs` | 把源文本切成与渲染器块序列平行的结构，产出每个块的源行跨度 |
| 归因计算 | `provenance.rs` | 块/源行 → 渲染行数的换算，产出 `Vec<RowOrigin>` |
| 纯文本归因 | `provenance.rs` | `wrap_text` 类消息（User/Thinking/Status/Usage/Error）的按源行归因 |
| 代码块围栏跨度 | `app.rs` | `process_code_blocks` 额外返回每个围栏在源文本中的行跨度 |
| 行布局索引 | 新模块 `layout.rs`（或 `ui.rs`） | 消息块 → 内容行区间；供复制与现有 hit-test 共用 |
| 文本重建 | `provenance.rs` | 选中行区间 + 溯源 + 源文本 → 输出文本 |
| 复制触发适配 | `ui.rs` / `selection.rs` | `extract_selected_text` 改为调用文本重建，Buffer 仅作降级兜底 |

职责边界：

- `selection.rs` 只保留**鼠标几何、高亮、剪贴板写入**（`TextSelection`、`contains`、`osc52_copy`），不再承担文本提取。
- `provenance.rs` 不依赖 Buffer，只依赖"源文本 + 渲染器"，可独立单测。

## 5. 详细设计

### 5.1 溯源模型

概念上每行渲染结果属于二选一：

| 取值 | 含义 | 复制时的处理 |
|------|------|--------------|
| `Source { src_line }` | 该渲染行来自该消息源文本的第 `src_line` 行 | 输出源文本对应行的**原文**（assistant 即原始 Markdown） |
| `Decoration` | 无源文本对应：块间留白、底色分隔行、表格边框、引用块竖线、工具块框线、图片占位 | 回退输出该屏幕行的可见文本（`trim_end` 后）；**若整行全为空白则跳过** |

`msg_id` 由所属 `MessageCache` 隐含，不必存进每条溯源。

### 5.2 归因算法：拆碎 → 隔离渲染 → 取行数

统一套路（对 Markdown 与纯文本都适用）：

```
1. 把"渲染单元"切割成最小可归因单元（最小粒度 = 一个源行）
2. 对每个单元单独调用渲染器，取它产生的行数
3. 按顺序把行数累加，即为每一行渲染结果写下 src_line
4. 断言：所有单元行数之和 == 实际渲染行数；不等则整体降级
```

第 1、2 步的依据是 F2（段落逐源行独立折行）与 F4（块自包含），因此"隔离渲染的行数"与"完整渲染中的行数"相等。

| 渲染单元 | 最小单元 | 行数换算 |
|----------|----------|----------|
| `Paragraph(Vec<String>)` | 每个源行 | 该源行单独走行内解析 + 折行所得行数 |
| `Heading1/2/3` | 块本身 | 1 行 ↔ 1 源行 |
| `ListItem` / `TaskItem` | 块本身（文本内可含 `\n`） | 用与渲染器相同的拼接文本（缩进 + 标记 + 内容）折行计数 |
| `BlankLine` / `HorizontalRule` / `InlineCode` | 块本身 | 1 行 ↔ 1 源行（或 0 行） |
| `Table` | 块本身（本期降级） | 整块标 `Decoration` |
| `Blockquote` | 递归其 children | 前缀竖线行为 `Decoration`，子块按其自身规则归因 |
| `Image` | 块本身 | 1 行 ↔ 1 源行 |
| 纯文本类消息 | 每个 `content.split('\n')` 行 | `wrap_text(line, width)` 的行数（`wrap_text` 先按 `\n` 切分再逐段折行，可加性成立） |
| 代码块 | 每个高亮行（= 一个源行） | `wrap_styled_line(line, inner_w)` 的行数 |
| 流式区域 | 每个 `streaming_text` 行 | 恒为 1（流式渲染不做折行，见 `ui.rs:841`） |
| 子 tab task prompt | 每个折行后的行 | 折行行数（源为 prompt 原文） |

### 5.3 源行对齐（块序列 → 源行跨度）

因为 F5（`MarkdownBlock` 不带位置信息），必须由我们自己把"块序列"与"源行"对上。

**推荐策略 S1：结构性扫描 + 逐块校验**

```
1. 预处理阶段（process_code_blocks）已知每个围栏的源行跨度（F6），先把这些区间从
   "待对齐源行"中排除并记入块清单的对应位置
2. 对剩余源行做轻量块级扫描，按行特征识别与渲染器同构的块序列：
     空行 / 标题(#) / 列表(- * +) / 任务列表(- [ ] - [x]) / 引用(>) /
     表格(|...|) / 水平线(--- *** ___) / 段落(连续普通行)
3. 与渲染器产出的 blocks 逐个配对，校验：块种类一致 + 文本内容一致
   （例如标题去掉 # 后与块内文本相等；段落的行数与文本逐行相等）
4. 任一处不一致 → 判定对齐失败 → 从该处起整体降级为 Decoration
```

要点：

- 扫描器只做**块级**识别，不解析行内语法，复杂度可控。
- 每个块的源行跨度一旦确定，块内再按 5.2 的最小单元细分到每个源行。
- 强制校验 + 失败降级，保证"要么正确、要么退回旧行为"，不会静默产生错位文本。

**备选策略（供讨论）**

| 策略 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| S1（推荐） | 自写块级扫描 + 校验 | 无副作用、可单测、失败可检测 | 需覆盖渲染器的块识别规则 |
| S2 | 用渲染器自身的解析器做**前缀解析**，按"块终态首次出现的位置"反推跨度 | 不重写识别逻辑 | O(n²) 解析；表格/引用块等"增量增长"结构需要额外稳定性判据 |
| S3 | 解析前在源行注入不可见锚点（复用 `\x00` 机制），渲染后剥离并读回源行号 | 归因最直接 | 会扰动解析；水平线、表格分隔行、空行无法承载锚点，仍要退回 S1 的规则 |

### 5.4 代码块归因

`process_code_blocks`（`app.rs:169`）目前返回 `(处理后文本, 高亮行列表)`，需**额外返回**每个围栏的源行跨度 `(起始行, 结束行)`。

- 源文本中该围栏的**每一行**（含 ` ```lang ` 与结尾 ` ``` `）都是 `ChatLine.content` 的行，各自有待归因的渲染行；
- 渲染阶段把标记行展开为 `sum(wrap_styled_line(高亮行, inner_w).len())` 行，这些行依次对应代码块内的源行；
- 高亮行与源行的对应关系：`highlight_code_block` 保持"一源行 → 一高亮行"，围栏行本身对应标记行展开前的占位。

注意：解析器看到的是 `\x00CODEBLOCK_{n}\x00` 标记，它会被归为一个普通块（段落或行内代码），因此 5.3 的对齐步骤必须**优先识别标记文本**，并直接使用第 1 步记录的围栏跨度，而不是走通用段落规则。

### 5.5 流式区域与 task prompt

- 流式区域：`streaming_display_text()`（`app.rs:399`）是**原始 Markdown**（未渲染），渲染时 `stream_text.lines()` 逐行输出、不折行（`ui.rs:841`）。因此源行与渲染行**严格 1:1**，归因退化为恒等映射。
- task prompt：渲染为 `📋 {prompt}` 并折行（`ui.rs:753`）。源取 prompt 原文时，每行归因到折行前的源行；本期可先整体标 `Decoration`。

### 5.6 装饰行

块之间的留白来自 `BlockStyle`（`theme.rs:153`）：`total_height = top_margin + margin_vertical + line_count + bottom_pad`。这些行不对应任何源文本：

- 内容行在块内的偏移 = `top_margin + margin_vertical`；
- 留白行标 `Decoration`，复制时**全空白则跳过**，避免选区跨消息时插入多余空行；
- 消息内真正的空行（`BlankLine`）是 `Source`，其源行本身为空行，输出空行是正确行为。

### 5.7 行布局索引（内容行 → 消息块）

复制需要把选区行号换算到"哪条消息的第几行"。

现有代码已有同样逻辑：`tool_block_hit_test`（`tool_ui.rs:582`）与 `agent_open_tab_hit_test` 都在"累加 `style.total_height(cache.line_count)`"的循环里定位消息。

设计：抽出**唯一**的行布局索引函数，输入 `messages + message_caches + 渲染宽度 + prompt_h`，输出每个块的行区间与 `msg_id`，供三处共用：

| 使用方 | 现状 | 改造后 |
|--------|------|--------|
| 工具块点击 hit-test | `tool_ui.rs:582` 自带循环 | 复用索引 |
| "[show in new tab]" 按钮 hit-test | 自带循环 | 复用索引 |
| 复制行 → 消息 | 无（直接读 Buffer） | 复用索引 |

坐标约定（与现有 hit-test 一致，不引入新约定）：

```
选区行 = 屏幕 row + scroll_y
内容行 = 选区行 - chat_area_rect.y
消息行 = 内容行 - prompt_h        ← 与 event.rs:860 的处理一致
```

注意事项：

- `tool_block_hit_test` 目前从 `y = 0` 开始、不扣 `prompt_h`（由调用方扣），合并后需明确由索引函数承担 `prompt_h`，并保留现有测试语义（`tool_ui.rs:1089` 起）或同步更新。
- 布局索引必须在**缓存已对齐**时使用。`render_chat_area` 内已调用 `ensure_all_caches`（`ui.rs:677`），复制发生在同帧渲染末尾（`ui.rs:435`），因此天然一致。

### 5.8 文本重建规则

输入：选区矩形 + 行布局索引 + 各消息溯源 + 源文本。

```
按内容行从上到下遍历选区内的行：
  1. 定位该行所属区域（消息块 / 流式区 / prompt / 其他 ui）
  2. 消息块内 → 取该消息溯源对应项
       Source{src_line} → 标记"需要输出源文本的 src_line 行"
       Decoration       → 若该屏幕行去空白后为空 → 跳过；否则作为独立输出行
  3. 相邻且来源相同的源行只输出一次（同一源行折出的多行自动合并）
  4. 其余区域（输入框/状态栏/分隔线等）→ 按 Decoration 处理
输出：按上述顺序拼接，源行之间以换行分隔
```

行为规则：

| 情况 | 结果 |
|------|------|
| 选区完整覆盖若干源行 | 输出这些源行的原文，含原始 Markdown 语法 |
| 选区只覆盖某源行的一部分（列级） | 输出该源行**完整原文**（粒度到行，接受略多） |
| 选区跨越消息边界 | 各消息按上述规则依次输出，块间留白不产生空行 |
| 选区包含表格/引用块/工具块 | 本期为 `Decoration`，回退屏幕文本（仍是问题①的形态） |
| 归因失败 | 整条消息（或该区域）回退 `Buffer` 文本，即当前行为 |

### 5.9 构建时机与成本

**按需构建，不做长期缓存。** 复制是人工频率事件（秒级间隔），而单条消息的溯源构建成本 = 一次 Markdown 解析 + 若干次隔离渲染 + 一次块级扫描，量级与既有单条消息渲染同阶。

不做缓存的原因：避免引入 `(msg_id, version, width)` 之外的第二套失效逻辑；`width`/`version` 变化时缓存本身就会重建。

```
复制触发（ui.rs:435）
  → 行布局索引（O(消息数)，复用已有累加循环）
  → 对涉及到的消息按需构建溯源（通常 1~2 条）
  → 文本重建 → pending_copy_text
```

## 6. 依赖关系

```
provenance.rs  ──依赖──> ratatui-markdown 公共 API（parse / 行内解析 / 折行）
               ──依赖──> app.rs 的 wrap_text / wrap_styled_line / process_code_blocks
               ──依赖──> theme.rs 的 BlockStyle
               ──不依赖──> ratatui Buffer、selection.rs、ui.rs

layout.rs      ──依赖──> theme.rs（BlockStyle）+ MessageCache
               ──被依赖──> ui.rs、tool_ui.rs（hit-test）、provenance.rs（行→消息）

selection.rs   ──保留──> 几何 / 高亮 / osc52_copy
ui.rs          ──调用──> provenance.rs（构建 + 重建）
```

## 7. 核心数据流

```
鼠标拖拽
   └─ event.rs 更新 text_selection（屏幕 column / row + scroll_y）

左键抬起
   └─ pending_copy = true

下一帧 render
   ├─ render_chat_area
   │    ├─ ensure_all_caches(app, render_w)        ← 渲染缓存对齐
   │    ├─ 按当前 scroll 绘制消息块 + 流式区
   │    └─ （布局参数：prompt_h / cache_width / chat_area_rect 已在 app 中）
   └─ pending_copy 处理（ui.rs:435）
        ├─ 行布局索引：选区内容行 → (msg_id, 块内行)
        ├─ 对涉及消息构建溯源：源文本 → 块序列 → 源行跨度 → 每行 src_line
        │     └─ 任一步校验失败 → 该消息降级
        ├─ 文本重建：Source → 源行原文；Decoration → 屏幕文本；全空白跳过
        └─ pending_copy_text = 结果

draw 返回后（event.rs:307）
   └─ 写系统剪贴板
```

## 8. 不做什么

| 不做 | 原因 |
|------|------|
| 分行内列级的精确裁剪 | 溯源粒度到源行即可满足主要诉求；列级需要字符级映射，成本与收益不匹配 |
| 表格 / 引用块的精确归因 | 本期统一降级 `Decoration`，后续按同一套"拆碎-隔离渲染"方法扩展 |
| 工具块（`ToolCall`/`AgentCall`/`ToolResult`/`ToolError`）的归因 | 由 `tool_ui.rs` 各渲染器自行折行/截断，需要它们各自产出溯源，属于二期 |
| 改动渲染器的折行行为（例如关闭库内折行改自管） | 会带来视觉回归风险，违背 G3 |
| fork / patched `ratatui-markdown` | 前缀差分与隔离渲染已验证可行，无需引入上游维护成本 |
| 反向把渲染结果解析回 Markdown | 不可靠；原文一直存在，无必要 |
| 复制时保留屏幕上的行内样式 | 目标产物是纯文本；用户诉求是完全可用的原始 Markdown |

## 9. 验收标准

| 编号 | 验收项 | 判定方式 |
|------|--------|----------|
| A1 | 长段英文/Markdown 段落在窄终端下折行，复制结果无多余换行 | 渲染真实管线后构造选区，断言输出与源行相等 |
| A2 | 复制 assistant 消息得到原始 Markdown（`#`、`**`、`- `、围栏、表格 `|`） | 同上，断言输出等于 `ChatLine.content` 的对应行区间 |
| A3 | 复制含代码块的消息，围栏与代码内容为原始文本，高亮不泄漏到结果 | 断言包含 `` ```lang `` 与原文缩进 |
| A4 | 同一源行折出的多行被选中时只输出一次 | 断言无重复 |
| A5 | 跨消息选区（user → assistant → tool）输出顺序正确、块间无多余空行 | 断言精确字符串 |
| A6 | 表格/引用块/工具块选区输出与改造前一致（降级路径生效） | 回归对比 |
| A7 | 归因失败时不 panic，输出回退为改造前行为 | 构造畸形源文本（未闭合围栏、混合 setext、错位表格）验证 |
| A8 | 视觉零回归：渲染快照与改造前逐字节一致 | 现有渲染测试全通过 |
| A9 | 单条消息复制耗时与改造前同阶（毫秒级） | 长消息（500+ 行、含多个代码块）实测 |

## 10. 风险与降级

| 风险 | 影响 | 缓解 |
|------|------|------|
| 块级扫描与渲染器识别规则不一致（setext 标题、缩进代码块、嵌套引用、表格边界） | 对齐失败 | 强制逐块校验；失败整体降级；A7 用例覆盖 |
| 归因行数与实际渲染行数不等 | 行错位，复制出错误文本 | 构建末尾断言总和相等，不等即降级（宁可退回旧行为） |
| `ratatui-markdown` 升级后块识别或折行变化 | 归因失效 | 断言机制使失效表现为降级而非错误；单测覆盖"隔离渲染行数 == 完整渲染行数"这一前提 |
| `highlight_code_block` 行数与源行不一一对应（尾部空行、`\r\n`） | 代码块归因错位 | 仅对代码块做前后行数校验，不等则代码块整体降级 |
| 溯源构建成本在超长消息上偏高 | 复制卡顿 | 按需构建 + A9 实测；必要时对单消息溯源做短期缓存 |
| 布局索引重构影响现有 hit-test | 点击行为回归 | 复用同一函数并保留/更新现有 hit-test 测试（`tool_ui.rs:1089` 起） |
