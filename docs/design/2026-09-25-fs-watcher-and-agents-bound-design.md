# 设计文档：跨平台文件监听模块 `visp-fs` 与 AGENTS.md 向上边界

- 日期：2026-09-25
- 状态：v5（经四轮独立评审；第四轮发现 1 P1 机制归属错误 + 9 P2 规格缺口，本轮全部处理；待用户最终确认）
- 起因：`/reload` 特性冒烟测试中发现的两处问题（见 §1）
- 涉及 crate：新增 `visp-fs`；改动 `visp-codegraph`、`visp-daemon`、`visp-config`、workspace 根

**v5 修订要点**（相对 v4）：

- **P1-A（机制归属纠正，关键）**：v4 把 §4.3「细则 2」（Remove 命中仍存在的路径 → 重挂）标为**防御性**，并称原子替换的新路径由「目录 diff 的 Create」覆盖——**与 kqueue 实际行为不符**。核对 notify 7 kqueue 源码：目录 `NOTE_WRITE` 的 diff 逻辑是「找出**不在 notify watch 集合里**的条目」，而原子替换的对象路径**仍在集合中**（旧 inode 的卸载要等本批 drain 结束后才应用），因此**不会补发 Create**；替换后该路径的文件级 watch 失效，之后「原地覆写」不再产生事件。**故细则 2 是 kqueue 下原子替换的「必需主路径」，不是防御性兜底。**
  - 处置：细则 2 **拆为两条**——**(2a) 必需主路径**：Remove 命中**仍存在**的路径 = 原子替换 → **立即重挂**并向消费者投递 `创建`；§7.1.2 显式引用。(2b) **防御性**：Create/Remove 乱序下的互斥保护（后端不可自然触发，假体单测）。
  - 同时更正 §4.6 相应表述：「重命名为**新名**」→ 新路径可由目录 diff 的 Create 可靠覆盖（新名必不在集合中）；「**覆盖同名已监听路径**的真·原子替换」→ **由细则 2a 的探测恢复**，不由目录 diff。
- **P2-B（事件形态归属纠正）**：v4 把 `RenameMode::Both` 错记给 Windows，并在 §4.6 漏掉 inotify 的 `Both`。更正为：**kqueue** `Any`（单路径，旧）；**inotify** `From`(旧) / `To`(新) / **`Both`(旧+新)**；**Windows** 仅 `From`(旧) / `To`(新)（**无 Both**）。归一化表补 `Both → 删除(旧)+创建(新)`；§4.8 的「四类后端事件形态」改为**三类后端**。
- **P2-C（目录抑制判定范围）**：v4 承诺「目录条目级 Modify 抑制」的判定依据是「模块自身维护的目录监听集合」——但**递归目标的子树目录不在该集合中**（模块只挂了递归根），承诺对子树目录不成立。**限定**：抑制保证仅覆盖「**模块直接挂载的目录**」；**递归目标的子树目录条目级 Modify 不保证抑制**（消费者应幂等处理；如 daemon 的 `Matcher::Any` 目标会多一次无语义的重扫，幂等无害）。
- **P2-D（codegraph 残留形态纠正）**：v4 称「旧路径的**符号**永久残留索引」**不准确**。实情：`FileEvent::Modified` 分支**先** `delete_by_file`（删 `symbols`）**后**读文件；旧路径读失败时**符号已删**，真正残留的是 `edges/imports/exports/files` 等**未被 `delete_by_file` 清理**的行（dangling 行）。据此更正 §4.6 的「附带发现」，并调整 §6 的风险表述（该缺陷仍在，但定性更准）。
- **P2-E（模式定义与子目录事件）**：§4.2「直接子级 = 直接子**文件**」与 §4.3 / daemon 目标 #6 / G5 补挂链需要**子目录创建事件**矛盾。改为「根目录的**直接子项（文件与目录）**」。
- **P2-F（验收 7.1.1 失真）**：kqueue 在目录 diff 发现**新建**文件时会**自动补挂**该文件，故「监听启动后再创建→再覆写」**即使不做模块级文件监听也会通过**，无法复现原始盲区。7.1.1 改为「文件在**监听启动之前**已存在」。
- **P2-G（降级语义缺口）**：细则 4（忽略挂载失败 + warn）与 §4.2「资源耗尽须**显式报错降级**」张力；且**若目标根 / 最近存在祖先自身挂载失败**，上层无任何监听 → Create 永不到来 → 功能静默永久缺失。处置：**区分两级**——(细则 4) **单文件级**挂载/重挂失败 → 忽略 + 不入集合 + warn（可被后续事件恢复）；(细则 5) **根 / 最近祖先级**挂载失败 → 属「资源耗尽/不可用」类，**必须显式上报降级**（不得静默）+ 有界重试；**无任何可挂载祖先时终止并显式上报「自动监听不可用」**。
- **P2-H（`$HOME` 未定义）**：§5.1 补：`$HOME` 不可解析时**只加载项目层**、不向上。
- **P2-I（能力判定谓词）**：§4.2 为「具备全量重扫能力」给出判定谓词：**收到任一事件即对所属领域做一次全量读盘重建**（daemon 属此类；codegraph 逐文件 upsert，不属此类）。

**v4 修订要点**（保留备查）：修 G2 与 §4.6 的类型矛盾；乱序分支定位校准（**此项在 v5 被 P1-A 纠正**）；重扫兜底按消费者能力分类；补细则 4；目录 Modify 抑制判定依据；归一化表补元数据变更；验收 7.1.8 措辞。

**v3/v2 修订要点**（保留备查）：重命名降级为语义糖；kqueue 多文件创建漏报；幂等重挂定死 + 三细则；Windows 事实更正；资源上限不承诺；`$HOME` 含层与 CI 迁移路径；缺口是 kqueue 特有（inotify 靠内核冒泡）。

## 1. 背景

`/reload` + 自动热重载特性已交付并通过全量质量门，但 daemon 侧端到端冒烟暴露两个问题：

**问题 1（kqueue 下的内容改写漏检）**：自动热重载的「祖先目录里的 AGENTS.md」采用**非递归目录监听**。macOS 上 notify 走 **kqueue** 后端（workspace 显式启用 `macos_kqueue`），实测：**已存在文件的纯内容覆写不触发、原子替换（tmp+rename）与新建触发**。

经核对 notify 7 的实现，该缺口的确切范围是：

| 后端 | 目录监听能否感知**已存在子文件的内容修改** | 机制 |
|---|---|---|
| kqueue（macOS，**我们启用的**） | **❌ 非递归目录监听不行**；递归可以 | 递归时对子树**每个文件**建 vnode watch（`NOTE_WRITE`）；非递归只挂目录 |
| inotify（Linux） | ✅ 可以（递归与非递归皆可） | **内核冒泡**：目录被监听时，其内文件的事件会以带 `name` 的形式上报（`IN_MODIFY`） |
| ReadDirectoryChangesW（Windows） | ✅ 可以 | `FILE_NOTIFY_CHANGE_LAST_WRITE` |
| FSEvents（macOS 默认） | ✅ 可以 | 子树级 |

**结论**：**缺口是 kqueue（非递归目录监听）特有**；但「**显式对文件做监听**」这一修复策略在三类后端都成立且无害（在 inotify/Windows 上属冗余）。因此本设计以**结果级契约**（而非后端分支）来统一定义语义。

**问题 2（AGENTS.md 向上查找无界）**：`discover_agents_md` 从项目目录**一路向上到 `/`**，沿途每个 AGENTS.md 都加载。存在「离项目很远的祖先目录（如 `~/Documents/AGENTS.md`）静默作用于本项目」的意外泄漏风险。同时 visp 已有独立的「全局 AGENTS.md」通道（`~/.config/visp/AGENTS.md`），无界向上属冗余。

现有 watcher 是**两份各自实现**：`visp-codegraph/src/watcher.rs`（索引器用）与 `visp-daemon/src/watch.rs`（热重载用），平台适配逻辑分散、无法统一保证语义。

## 2. 目标

1. **抽出共享文件监听模块 `visp-fs`**，对外承诺一个**明确、可移植的语义契约**；后端差异由模块内部吸收。
2. **迁移** `visp-codegraph` 与 `visp-daemon` 两处 watcher 到 `visp-fs`，消除重复实现。
3. **修复** AGENTS.md 内容改写漏检（由新契约的 G1 自然覆盖）。
4. **AGENTS.md 向上查找止于 git 根**，消除跨项目泄漏。

## 3. 非目标

- 不引入新的第三方依赖（继续用 workspace 已有的 `notify`）。
- 不切换到 FSEvents 后端（保留 `macos_kqueue` 现状；新契约为结果级，后端选择不改变契约）。
- 不引入周期性轮询兜底（保留为未来极端环境备选）。
- **不统一两处消费者的 debounce**：聚合键不同（daemon 按**领域** 200ms；codegraph 按**路径** 500ms），下沉会让事件源背负消费者语义；debounce 留在各消费端。
- 不改动 daemon.toml 的热重载范围、不改 reload 核心的既有行为。
- `visp-fs` 只做**监听**，不做通用文件 IO（命名虽为 fs，本次只交付 watcher）。

## 4. Part 1 — `visp-fs` 文件监听模块

### 4.1 归属与形态

- 新增 crate `visp-fs`；两个消费者各加一条 workspace 依赖。
- **依赖方向约束**：`visp-fs` **不得**依赖 `visp-core` / `visp-config` / `visp-daemon` / `visp-codegraph`（领域类型留在消费端，契约只含「路径 + 事件类型」）。这是它必须独立成 crate 的理由：`visp-codegraph` 不依赖 `visp-config`，若放 `visp-config` 会给 codegraph 引入无关依赖；放 `visp-daemon` 会导致 codegraph 反向依赖 daemon（循环）；`visp-core` 语义混杂。
- 模块内部封装对 `notify` 的使用；迁移后 `visp-codegraph`、`visp-daemon` 移除对 `notify` 的直接依赖（已确认两者除此之外无其它用途）。

### 4.2 语义契约（本设计的核心）

消费者声明若干**监听目标**，每个目标 = `(根路径, 模式, 过滤规则)`，模式二选一：

- **递归**：根目录及其整个子树。
- **直接子级**：根目录的**直接子项（文件与目录）**（其中可能只有部分符合过滤规则）。
  > **必须包含子目录**：结构性事件中的「目录创建」是 G5 补挂链与 daemon 目标 #6（`.visp/{rules,agents,skills}` 出现）的前提，故模式定义不得只写「文件」。

模块承诺：

| # | 保证 |
|---|---|
| **G1** | 匹配的**已存在文件**，其**通过常规写入路径（`write` / `truncate` / `rename`）产生的**内容修改，在**本模块支持的后端集合**上均上报事件 |
| **G2** | 对匹配文件的**创建、删除**上报事件；**重命名**以 §4.6 的「**删除(旧) + 创建(新)**」**等价形式**覆盖（**不存在独立的「重命名」事件类型**） |
| **G3** | 事件以「路径 + 事件类型」的形式投递，类型集合见 §4.6（`创建` / `修改` / `删除`） |
| **G4** | **不**保证事件顺序、不保证合并、**不保证去重**——一次逻辑保存可能产生多个/多种事件，消费者自行防抖。（注：主路径的事件链路**实测保序**，此条为**契约免责**） |
| **G5** | **允许根路径不存在**：自动监听最近的存在祖先，根出现后自动挂载；并发出**「需要重新扫描」信号** |

**「本模块支持的后端集合」的定义**：当前为 workspace 特性锁定下的 `inotify`（Linux）/ `macos_kqueue`（macOS）/ `ReadDirectoryChangesW`（Windows）。**若移除 `macos_kqueue` 特性改用 FSEvents，契约范围需重新评估**（FSEvents 有聚合/延迟特性，事件粒度不同）。

**明确不承诺**（写入契约，避免隐式假设）：

| 不承诺项 | 说明 |
|---|---|
| **kqueue 多文件同窗口创建** | 同一目录在**同一事件合并窗口内创建多个文件**时，kqueue 后端**可能只上报第一个**创建事件（其余直到下次目录条目变化才被发现）。**兜底按消费者能力分类**：<br>・**具备全量重扫能力**（判定谓词：**收到任一事件即对所属领域做一次全量读盘重建**。daemon 属此类：任一文件事件 → 领域全量重扫）**可自然收敛**；<br>・**纯增量**消费者（如 codegraph：逐文件 upsert，不具备上述谓词）**存在已知残余风险**——漏报文件在下次目录条目变化前不被监听、其内容编辑不被感知；兜底手段为**手动重建索引**。<br>消费者不得假设创建事件完备 |
| **递归子树目录的条目级 Modify** | 见 §4.6 末行：抑制保证**仅覆盖模块直接挂载的目录**；递归目标的**子树目录**条目级 Modify **不保证抑制**（消费者应幂等处理） |
| **监听资源上限** | inotify `max_user_watches`（老内核/受限容器默认 8192，大 repo 递归监听会触顶）、Windows 句柄流数量。资源耗尽时模块**显式报错降级**（见 §4.3 细则 5），**不得静默丢事件** |
| **跨文件系统 / 网络文件系统** | NFS / SMB / 容器 bind mount / 跨挂载点的监听事件不承诺 |
| mmap 写入 | inotify 明文不产生 `IN_MODIFY`（如某些数据库/内存映射写入） |
| 经监听目录之外路径的写入 | 如硬链接：经非监听路径写同一 inode 不产生事件 |
| **符号链接是否跟随** | notify 递归默认 `follow_links(true)`——**会**跟随 symlink 目录树，可能监听跟出根之外。本模块**沿用该默认**（跟随），并在此明示 |
| 大小写不敏感 | 匹配为字符串精确匹配；APFS 默认大小写不敏感下 `agents.md` 与 `AGENTS.md` 可能漏匹配 |
| 事件精确计数/时序 | 见 G4 |
| 跨进程一致性 | — |

**消费者义务**：事件与重扫信号均为**幂等输入**——消费者不得依赖计数、顺序、配对或唯一性；收到事件/信号后应做全量或增量的幂等处理。

### 4.3 实现策略（默认策略；允许后端特化）

- **递归目标**：交由 notify 的递归能力。
  - kqueue 下它**为子树每个文件建 watch**（内容改写可感知）；
  - inotify 下它**只挂目录**，内容感知依赖**内核冒泡**；
  - Windows 下依赖 `LAST_WRITE`。
- **直接子级目标（默认策略）**：**目录监听负责结构性事件（创建/删除；重命名按 §4.6 语义糖）**，**同时对每个匹配的直接子文件单独挂文件级监听**负责内容修改。文件级监听在三类后端都会在内容写入时触发，因此这是**跨平台成立**的做法（在 inotify/Windows 上冗余但无害）。
  - **在 Windows 上目录监听不可省**：单文件流会过滤掉 rename 的**新名**，只有目录流能看到新名（不是为内容修改——那是目录流天然有的）。
- **文件级挂载必须幂等**：对 Create / Rename 涉及的路径**无条件 `unwatch + watch` 重挂**。
  - **不做 `(dev, inode)` 键控**：其判定依赖事件完整性，Remove/Create 乱序会污染键状态，恰好复刻被否掉的「路径在集合就跳过」错误模式；且它省不掉路径级 watch 管理（三后端 unwatch 均按路径）。系统调用放大可忽略（仅 Create/Rename 触发，2N vs N 的线性常数差）。
  - **细则 1**：`unwatch` 报 `watch_not_found` **必须忽略**——notify 在文件被删除时**已自动移除** watch（kqueue/inotify/Windows 皆然），故「删除→卸载」多数是二次卸载。
  - **细则 2a（必需主路径，P1-A 纠正）**：处理 Remove（卸载）前**先探测路径是否仍存在**——**仍存在** ⇒ 发生了**覆盖同名路径的原子替换**（tmp+rename）⇒ **立即重挂该路径**，并向消费者投递 `创建`（该路径的文件级 watch 已随旧 inode 失效，且 **kqueue 的目录 diff 不会补发 Create**，因为该路径仍在 notify 的 watch 集合内——见下方机制说明）；**不存在** ⇒ 正常卸载。
  - **细则 2b（防御性）**：Create / Remove **乱序**下的互斥保护（避免「Create 先到、Remove 后到」把刚挂的 watch 拆掉）。后端**不可自然触发**（内核事件队列按发生序 → notify 单线程消费 → channel FIFO），以**假体单测**覆盖，不作为验收主路径。
  - **细则 3**：**不依赖** notify 在 kqueue 的 `Vnode::Link` 内部「remove + readd 整个子树」行为（该行为昂贵且是实现细节）。
  - **细则 4（单文件级失败）**：**单文件级**挂载 / 重挂失败（含细则 2a 探测后 `watch` 报错，如 TOCTOU 下文件恰被删除）→ **忽略错误 + 该路径不计入监听集合 + warn**；后续该路径的 Create 事件会再次触发重挂，状态自然收敛。
  - **细则 5（根 / 最近祖先级失败，P2-G 新增）**：**目标根或最近存在祖先**的挂载失败 ⇒ **不是**单文件级可恢复情形（上层没有任何监听，Create 永不到来）⇒ 属「资源耗尽 / 不可用」类，**必须显式上报降级**（不得静默，可观测面见下）+ 有界重试；**若最终无任何可挂载祖先 ⇒ 终止并显式上报「自动监听不可用」**。
    - **「显式降级」的可观测面**：模块向消费者返回/暴露「降级状态与原因」；daemon 侧据此在启动日志与（若已连接）TUI 通知中体现，而非仅 `warn`。codegraph 侧保持「不可用时仅告警、不影响索引全量重建」。

**机制说明（细则 2a 为何是必需主路径）**：notify 的 kqueue 后端在目录 `NOTE_WRITE` 时，用「找出**当前不在其 watch 集合里**的条目」来做 diff（`find(|f| !watches.contains_key(f))`）；而原子替换的对象路径**仍在集合中**（旧 inode 的 watch 卸载延迟到本批 drain 结束后应用），故**不会**为它补发 Create。因此：
- 「重命名为**新名**」→ 新名必不在集合中 → 目录 diff 的 Create **可靠覆盖**；
- 「**覆盖同名已监听路径**」的真·原子替换 → **只有细则 2a 的存在性探测能恢复**。

- **维护监听集合**：记录已挂载的目录与文件路径，用于停止时释放；**去重的目标是「不产生重复的监听状态」，而非「跳过必要的重挂」**。
- **缺目录降级**（承接 G5）：根不存在时监听最近存在祖先 + 过滤；目录被创建后补挂，并发出重扫信号。**校准为事件驱动、批次内收敛**——因不承诺表中的「kqueue 多文件创建漏报」，这**不是竞态兜底而是结构性依赖**（对具备全量重扫能力的消费者成立，见 §4.2 判据）。
- **运行中目录目标被删/重命名**：等价于「根不存在」——转入降级监听并保持可恢复（重新创建后自动补挂）。
- **目录级重挂的成本注记**：kqueue 对目录的 `unwatch`/`watch` 是 **O(子树)**（递归 WalkDir 逐个文件增删 watch）。目录创建/重命名事件低频，可接受；**实施者不得对目录目标做高频重挂**（文件级重挂不受此限）。
- **平台特化**：模块内**优先不写 `cfg(target_os)`**；若某后端确需特化（如 Windows 文件级 watch 实为「监听父目录 + 按路径过滤」），**适配点集中于本模块内**，契约仍只承诺 G1–G5 的**结果**。
  - **Windows 事实**：每个 `watch()` 创建**独立**的父目录句柄与目录流，**没有引用计数**；真正陷阱是 notify 对**同路径重复 `watch` 会覆盖旧状态而不关闭旧句柄（泄漏）**——故「先 unwatch 再 watch」在 Windows 上是**必须**的（恰好支持本节的幂等重挂）。反复 unwatch/watch 安全。
  - 若未来启用 FSEvents（流模型），文件级 watch 概念不适用，属适配点内的后端特化。

### 4.4 目标声明与过滤规则（只述职责，不写签名）

- **目标声明**：表达 §4.2 的 `(根, 模式, 过滤规则)` 列表。
- **过滤规则**（支持现有两处消费者的最小集合，不做通用 glob 引擎）：
  - **包含**：文件名匹配、扩展名匹配、前缀/子树匹配。
  - **排除**：路径组件级排除（codegraph 现有 `node_modules` / `.git` 需要）。
  - 注意扩展名**含点/不含点**两种书写习惯的兼容（codegraph 现状两种都用）。

### 4.5 接口职责（只述职责，不写签名）

- **启动/停止**：启动返回一个句柄；句柄 `stop` 后不再投递事件、释放全部监听。
- **事件投递**：向消费者提供的接收端投递事件；投递**不阻塞监听回调线程**。
- **重扫信号**：因缺目录补挂而发出（G5）；消费者幂等处理。
- **降级上报**（细则 5）：暴露「自动监听不可用/降级」状态与原因。
- **线程约定**：句柄与接收端应为 `Send`；接收端被 drop 后不 panic（静默停止投递或尽力投递）。
- **纯函数部分**（便于单测）：目标声明与路径匹配的**判定**、缺目录降级链的**解析**、事件类型**归一化**。

### 4.6 事件类型与归一化

**事件类型**：`创建` / `修改` / `删除`。

**「重命名」不作为独立事件类型，而是语义糖**：

> 契约定义「**重命名 ≡ 删除(旧路径) + 创建(新路径) 的等价物**」。实现**允许**把重命名**拆分投递**为这两个事件；**消费者不得依赖两者的配对、顺序，也不得依赖存在「重命名」事件**。

理由（**三类后端**事件形态根本不同，无法统一归一化为单事件）：

| 后端 | 重命名的实际事件形态 |
|---|---|
| kqueue | **`RenameMode::Any`**：单事件、**只携带旧路径**（新路径须由目录 `NOTE_WRITE` 的 diff 推出，报为 `Create`）——**单靠 rename 事件无法得到新路径** |
| inotify | `RenameMode::From`(旧) / `RenameMode::To`(新) / **`RenameMode::Both`(旧 + 新)**（`Both` 在 cookie 匹配时额外发出；**v4 曾误记为 Windows**） |
| Windows | 仅 `RenameMode::From`(旧) / `RenameMode::To`(新)；且**单文件流会过滤掉新名**，只有目录流能看到（**Windows 无 `Both`**） |

把「原子替换」归一化为单向单一事件需要**跨事件配对**（Remove+Create 时间窗关联）——启发式、引入延迟、与 G4「不保证顺序」**直接冲突**，且归一化被定位为**纯函数**（做不了跨事件关联）。故不做配对。

**归一化约定**：

| 底层情形 | 投递 |
|---|---|
| 新建文件 | `创建`(路径) |
| 内容写入（write/truncate/O_TRUNC） | `修改`(路径) |
| **元数据变更（chmod / mtime，如 `touch`）** | `修改`(路径)（**保守归一化**，宁可多一次幂等重扫） |
| 删除文件 | `删除`(路径) |
| 重命名为**新名** | `删除`(旧) + `创建`(新)；**顺序不保证**（新名由目录 diff 的 Create 可靠覆盖） |
| **覆盖同名已监听路径**的原子替换（tmp+rename） | `删除`(同名) + `创建`(同名)；**由 §4.3 细则 2a 的探测恢复**（kqueue 的目录 diff 不会补发 Create，见 §4.3 机制说明） |
| inotify `RenameMode::Both`（旧+新单事件） | 拆为 `删除`(旧) + `创建`(新) |
| **目录自身的条目级 Modify** | **抑制、不下发**（目录结构变化已由 `创建`/`删除` 覆盖）。**判定依据**：用**模块自身维护的「已直接挂载目录」集合**判断该路径是否是被直接挂载的目录（纯内存、无 IO、无 TOCTOU）；**不得**用 `path.is_dir()`。**范围限定**：抑制保证**仅覆盖模块直接挂载的目录**；**递归目标的子树目录**条目级 Modify **不保证抑制**（消费者应幂等处理） |

临时文件若命中过滤规则，其自身的创建/删除按普通事件处理（实现**不做**基于文件名的特殊抑制，避免依赖临时文件命名约定）。

**消费端容错要求**（迁移 codegraph 时必须满足）：消费者对「删除已不存在的路径」「创建已存在的路径」「对同一路径的多次`修改`」必须**幂等**。

> **附带发现（P2-D 修正）**：codegraph 现状对重命名确有缺陷，但**残留形态与 v4 描述不同**——`Modified` 分支**先**删 `symbols`（`delete_by_file`）**后**读文件，旧路径读失败时**符号已删**；真正残留的是 `edges` / `imports` / `exports` / `files` 等**未被 `delete_by_file` 清理**的 **dangling 行**（错误仅 `eprintln`）。本设计的「删除(旧) + 创建(新)」语义顺带修复该残留；仍属**非行为等价迁移**，需专项回归（见 §7.2），但风险定性据实下调（dangling 行而非符号残留）。

### 4.7 迁移

- **`visp-daemon/src/watch.rs`**：保留其**领域分类**（路径 → rules/skills/agents）与 debounce 聚合；把「监听计划构建 + notify 挂载 + 缺目录补挂 + 去重」下沉到 `visp-fs`。daemon 侧改为声明现有 9 类目标（出处见旧文档 `docs/design/2026-09-24-reload-design.md` **§5.6 表格**）并消费事件。
  - 现有 8 个集成测试将被**结构性改写**（构造路径经 `visp-fs` 接口），断言语义尽量保持。
  - 注意：现有 `rapid_writes_are_debounced_into_one_reload` 用例此前**恰好掩蔽了覆写盲区**（多次写入丢事件但「1 次重载」断言仍成立）；改写时须把「**原地覆写必须产生事件**」显式断言化。
- **`visp-codegraph/src/watcher.rs`**：把「递归监听 project + 扩展名过滤 + exclude 目录」表达为一个递归目标 + 包含/排除过滤；索引器消费事件的部分按 §4.6 的容错要求调整（**旧路径 → 删除索引条目；新路径 → 重插**）。
  - **明确决策：codegraph 忽略 `visp-fs` 的重扫信号**（现状：project 不存在时仅 warn 且无监听，索引器本就无用；lazy 启动 + 全量 `build_full` 兜底不受影响）。**其代价见 §4.2 不承诺表的「kqueue 多文件同窗口创建」行**（纯增量消费者无重扫兜底，残余风险 + 手动重建）。
  - 回归重点：索引新鲜度（事件丢失 → 索引陈旧且无报错，故必须专项回归），以及 rename 语义由「归为 Modified」变为「删除+创建」带来的行为变化（含 dangling 行的清理效果）。

### 4.8 可测试性

- 判定/降级链/归一化等纯逻辑：单测。
- 运行时：临时目录集成测试，**必须新增「**监听启动前已存在**的文件的原地内容覆写」与「原子替换后继续原地覆写」两个用例**。
  > **P2-F**：kqueue 在目录 diff 发现**新建**文件时会**自动补挂**该文件，故「启动后创建→再覆写」会通过、无法复现盲区；用例必须让文件**在监听启动前就存在**。
- **rename 归一化单测**：以**三类后端**的事件形态为输入断言输出为「删除(旧) + 创建(新)」——kqueue `Any`（单事件、仅旧路径）、inotify `From` / `To` / **`Both`**、Windows `From` / `To`。**不要**断言「收到重命名类型事件」（该类型不存在）。
- **乱序分支（细则 2b）**：后端**不可自然触发**，以**假体单测**覆盖并标注「防御性」。
- **集成测试必须后端无关**：断言一律用**有限时间轮询的最终收敛**，**不得**含 kqueue 特化断言——这样才能在 Linux（CI）与 macOS（开发机）双方言跑同一组用例。
- **后端承载面**：CI（`.github/workflows/rust.yml`）已是 `ubuntu-latest` → **inotify 有现成承载面**；**macOS（kqueue，主交付后端）无 CI runner（`release.yml` 的 macos runner 只 build 不 test），由开发机承担验证**。这一不对称须在实施计划中显式写明。

## 5. Part 2 — AGENTS.md 向上边界

### 5.1 规则

从项目目录向上遍历，逐层加载该层的 `AGENTS.md`（近的优先），**边界规则**：

1. 若某层目录含 `.git`（**目录或文件**，后者用于 git worktree / submodule）→ **处理完该层后停止**向上。
2. 若一路上未遇到 `.git` → 到 **`$HOME` 为止（`$HOME` 层本身**含在内**，与规则 1 的「处理完该层后停止」同构）**。
3. **项目不在 `$HOME` 之下（如 `/tmp/x`、`/opt/x`）→ 不向上**，只加载项目层自身的 `AGENTS.md`。
   > v1 曾写「到 `/` 为止」，那会让 `/tmp/AGENTS.md` 作用于 `/tmp` 下所有项目、在多用户主机上重新引入注入面。
4. **`$HOME` 不可解析**（`home_dir()` 返回 `None`）→ **只加载项目层**、不向上（P2-H）。
5. 独立的「全局 AGENTS.md」（`~/.config/visp/AGENTS.md`）**保持不变**。注意：它与 `$HOME/AGENTS.md`（规则 2 可能加载到的那一层）**是两个不同的文件、并存不互斥**。

### 5.2 理由

- git 根即「项目边界」的通用直觉；monorepo 仍正确（git 根在子包之上）。
- 与「全局 AGENTS.md」通道不重叠，消除「离项目很远的祖先目录静默生效」的意外泄漏。
- 非 git 项目退化为「到家目录为止」，绝不越过可写公共目录。

### 5.3 影响点（必须一致）

- **加载器**：`visp-config/src/rules.rs` 的 `discover_agents_md`（现状：无界到 `/`）。
- **监听计划**：`visp-daemon/src/watch.rs` 的目标 #1（`ancestors_inclusive`，现状：无界到 `/`）——必须与加载器用**同一套**边界解析。
- **抽取**：把「**祖先链（目录列表）**解析」抽为 `visp-config` 内的**单一函数**，加载器在其上查「存在的 AGENTS.md」，监听计划在其上生成监听目标。（评审已核对：两处现状逻辑一致、`home_dir()` 已是 `pub`、daemon 已依赖 `visp-config`，抽取可行且无隐藏耦合。）
- **时机差异（已知）**：监听计划在 daemon 启动时**快照**，加载器**每次重载重算**。运行中若发生 `git init` 等导致边界变化，可能出现「监视的层 ⊃ 加载的层」的分叉——**无害**（变化守卫兜底），但契约上以**加载器运行时语义为准**，监听为启动快照。

### 5.4 边界情况

| 场景 | 行为 |
|---|---|
| 项目即 git 根 | 只加载项目自身的 AGENTS.md |
| monorepo（项目是子目录） | 一路上溯至 git 根，沿途 AGENTS.md 全部加载 |
| 嵌套 git（submodule 内） | **最近的 `.git` 即边界** → submodule 内不加载父仓库的 AGENTS.md（submodule 视为独立项目，与 cargo/rust-analyzer 惯例一致） |
| git worktree（`.git` 是文件） | 同样视为边界 |
| 非 git 项目、位于 `$HOME` 之下 | 到 `$HOME` 为止（含 `$HOME` 层） |
| 非 git 项目、位于 `$HOME` 之外 | **不向上** |
| `$HOME` 不可解析 | 只加载项目层（P2-H） |
| **CI 项目位于 `$HOME` 之外（如 `/build/...`）** | 组织级祖先 AGENTS.md **不再生效**。**迁移路径**：改用全局通道（`VISP_CONFIG_DIR` 指向组织配置目录，其内 `AGENTS.md` 会被加载）或项目内 `.visp/rules/`。建议 release notes 明示，避免「升级后 CI 规则静默消失」 |

## 7. 验收标准

### 7.1 `visp-fs` 契约
1. **内容改写可感知（非递归目标，P2-F 修正）**：文件**在监听启动之前已存在**；启动后**原地覆写**其内容 → 收到「修改」事件（macOS kqueue 下必须通过；核心修复项）。
   > 不得写成「启动后创建再覆写」——kqueue 会对目录 diff 发现的新文件自动补挂，那样即使实现有缺陷也会通过。
2. **原子替换后仍可感知（§4.3 细则 2a 的直接验收）**：对**启动前已存在且已监听**的文件做 tmp+rename 原子替换 → **随后再原地覆写** → **仍收到「修改」事件**（kqueue 下目录 diff 不会补发 Create，故此处**必须**由细则 2a 的存在性探测恢复）。
3. **结构性事件**：创建/删除上报；**重命名按「删除(旧) + 创建(新)」拆分投递**且顺序不作断言（§4.6）；**元数据变更（chmod/touch）**归一化为「修改」；**inotify `Both`** 拆为删除+创建。
4. **目录条目级 Modify 被抑制**：对**模块直接挂载的目录**不产生无意义的「修改」事件（判定依据为模块的已挂载目录集合）。
5. **动态补挂**：目标目录不存在 → 运行中创建（含**创建子目录**）并写入 → 收到事件且触发一次重扫信号。
6. **监听状态收敛**：重复 create/delete 风暴下，**监听状态收敛正确、无句柄泄漏**（以监听集合大小/挂载次数断言）；`unwatch` 的 `watch_not_found` 被忽略且不报错；**单文件级挂载失败**（细则 4）不污染监听集合并可被后续 Create 事件恢复。
7. **停止清理**：`stop` 后不再投递、监听释放。
8. **根级失败显式降级（细则 5）**：模拟**无权限路径 / 资源耗尽 / 无可挂载祖先** → **显式上报降级**（不静默），且不影响调用方启动。（注：根路径**不存在**属 G5 降级监听，**不是**失败情形。）
9. **乱序保护（细则 2b，防御性）**：以假体单测验证「Create 先 / Remove 后」不会拆掉刚挂的 watch。

### 7.2 迁移与回归
10. **daemon 热重载**：原地覆写 `AGENTS.md` 现在能触发 rules 重载（本次缺陷的直接验收）。
11. **codegraph 索引器回归**：源文件原地覆写、原子替换、**重命名（旧路径的 dangling `edges`/`imports`/`exports`/`files` 行被清理、新路径被正确索引）**、exclude 目录内变更、无关扩展名事件零触发 —— 索引新鲜度正确。
12. **后端无关**：同一组 §7.1 集成测试在 **Linux（inotify，CI）** 与 **macOS（kqueue，开发机）** 均通过；用例中无 kqueue 特化断言。
13. `cargo test --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo fmt -- --check` 全绿。

### 7.3 AGENTS.md 边界
14. **止于 git 根**：在 git 根之上人为放置 AGENTS.md → 不被加载、不被监听。
15. **monorepo 正确**：子目录项目仍加载至 monorepo 根的各层 AGENTS.md。
16. **非 git 项目**：`$HOME` 之下止于 `$HOME`（含该层）；`$HOME` 之外**不向上**；`$HOME` 不可解析时**只加载项目层**。
17. **加载器与监听计划一致**：同一祖先链解析被两处共用（无「监听但不加载」或反之）。
18. **rename 归一化映射表单测**：§4.6 所述**三类后端**事件形态 → 「删除 + 创建」的映射全部有单测；乱序分支为防御性、以假体单测覆盖。
