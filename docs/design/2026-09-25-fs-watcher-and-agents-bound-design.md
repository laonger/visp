# 设计文档：跨平台文件监听模块 `visp-fs` 与 AGENTS.md 向上边界

- 日期：2026-09-25
- 状态：v2（v1 经独立评审后修订：1 项 P0 + 6 项 P1 + 契约缺口已处理；待用户最终确认）
- 起因：`/reload` 特性冒烟测试中发现的两处问题（见 §1）
- 涉及 crate：新增 `visp-fs`；改动 `visp-codegraph`、`visp-daemon`、`visp-config`、workspace 根

**v2 修订要点**（相对 v1）：

- **P0（去重策略重写）**：删除「已监听文件集合 + **绝不重复挂载**」——该策略在**原子替换**（tmp+rename，产生同路径 Create 事件）下会把新 inode 判为「已挂载」而跳过，导致后续原地覆写再次漏检，等于复活本设计要修的 bug。改为**文件级挂载幂等**：对 Create/Rename 涉及的路径**无条件 `unwatch + watch` 重挂**（或以 `(dev, inode)` 为集合键，inode 变化即视为新文件）。
- **P1-1（事实纠正）**：v1 §1 声称「inotify 的非递归目录监听同样只看目录条目」**错误**。经核对 notify 7 源码：**kqueue** 递归会把子树**每个文件**建 vnode watch（内容改写可感知），**inotify** 递归**只挂目录**、内容感知依赖**内核事件冒泡**（事件 name 字段携带文件名），非递归亦然——即 **inotify 与 ReadDirectoryChangesW 在目录监听下本就上报子文件内容修改**。故**缺口是 kqueue（非递归目录监听）特有**；而「显式文件级监听」作为修复策略在三类后端均成立且无害。§1/§4.3 据此改写。
- **P1-2（rename 归一化）**：新增 §4.6 明确定义 rename 的归一化语义，并给出 codegraph 消费端的容错要求。
- **P1-3（排除过滤）**：§4.4 过滤规则补「**排除**」一类（codegraph 现有 `exclude_dirs` 需要）。
- **P1-4（边界自相矛盾）**：§5.1 规则 2 改为**非 git 项目不向上**（或硬止于 `$HOME`），不再「到 `/`」——否则 `/tmp` 项目会加载 `/tmp/AGENTS.md`，重新引入注入面。
- **P1-5（G1 措辞）**：G1 限定为「通过常规写入路径（write/truncate/rename）的内容修改」，「支持平台」定义为 workspace 特性锁定的后端集合。
- **P1-6（cfg 软化）**：把「不写任何 `cfg(target_os)`」从硬约束降为**默认实现策略**，契约只承诺结果，允许后端特化、适配点集中在本模块。
- **契约缺口补全**：重复投递、运行中目录目标被删/重命名、符号链接（notify 默认 follow）、重扫信号幂等性、大小写不敏感、Send/Sync 与接收端 drop。
- **迁移与验收**：明确 codegraph **忽略重扫信号**、扩展名含点/不含点转换、两个 watcher 的集成测试将被**结构性改写**；验收补「原子替换后继续原地覆写仍触发」「rename 归一化单测」「Linux inotify 冒烟计划」；修正 §7.1.4 措辞。

## 1. 背景

`/reload` + 自动热重载特性已交付并通过全量质量门，但 daemon 侧端到端冒烟暴露两个问题：

**问题 1（kqueue 下的内容改写漏检）**：自动热重载的「祖先目录里的 AGENTS.md」采用**非递归目录监听**。macOS 上 notify 走 **kqueue** 后端（workspace 显式启用 `macos_kqueue`），实测：**已存在文件的纯内容覆写不触发、原子替换（tmp+rename）与新建触发**。

经核对 notify 7 的实现，该缺口的确切范围是：

| 后端 | 目录监听能否感知**已存在子文件的内容修改** | 机制 |
|---|---|---|
| kqueue（macOS，**我们启用的**） | **❌ 非递归目录监听不行**；递归可以 | 递归时对子树**每个文件**建 vnode watch（`NOTE_WRITE`）；非递归只挂目录 |
| inotify（Linux） | ✅ 可以（递归与非递归皆可） | **内核冒泡**：目录被监听时，其内文件的事件会以带 `name` 的形式上报（`IN_MODIFY`） |
| ReadDirectoryChangesW（Windows） | ✅ 可以 | `FILE_NOTIFY_CHANGE_LAST_WRITE` |
| FSEvents（macOS 默认） | ✅ 可以 | 子树级 |

**结论**：**缺口是 kqueue（非递归目录监听）特有**；但「**显式对文件做监听**」这一修复策略在三类后端都成立且无害（在 inotify/Windows 上属冗余）。因此本设计以**结果级契约**（而非后端分支）来统一定义语义。

**问题 2（AGENTS.md 向上查找无界）**：`discover_agents_md` 从项目目录**一路向上到 `/`**，沿途每个 AGENTS.md 都加载。存在「离项目很远的祖先目录（如 `~/Documents/AGENTS.md`）静默作用于本项目」的意外泄漏风险。同时 visp 已有独立的「全局 AGENTS.md」通道（`~/.config/visp/AGENTS.md`），无界向上属冗余。

现有 watcher 是**两份各自实现**：`visp-codegraph/src/watcher.rs`（索引器用）与 `visp-daemon/src/watch.rs`（热重载用），平台适配逻辑分散、无法统一保证语义。

## 2. 目标

1. **抽出共享文件监听模块 `visp-fs`**，对外承诺一个**明确、可移植的语义契约**；后端差异由模块内部吸收。
2. **迁移** `visp-codegraph` 与 `visp-daemon` 两处 watcher 到 `visp-fs`，消除重复实现。
3. **修复** AGENTS.md 内容改写漏检（由新契约的 G1 自然覆盖）。
4. **AGENTS.md 向上查找止于 git 根**，消除跨项目泄漏。

## 3. 非目标

- 不引入新的第三方依赖（继续用 workspace 已有的 `notify`）。
- 不切换到 FSEvents 后端（保留 `macos_kqueue` 现状；新契约为结果级，后端选择不改变契约）。
- 不引入周期性轮询兜底（保留为未来极端环境备选）。
- **不统一两处消费者的 debounce**：聚合键不同（daemon 按**领域** 200ms；codegraph 按**路径** 500ms），下沉会让事件源背负消费者语义；debounce 留在各消费端。
- 不改动 daemon.toml 的热重载范围、不改 reload 核心的既有行为。
- `visp-fs` 只做**监听**，不做通用文件 IO（命名虽为 fs，本次只交付 watcher）。

## 4. Part 1 — `visp-fs` 文件监听模块

### 4.1 归属与形态

- 新增 crate `visp-fs`；两个消费者各加一条 workspace 依赖。
- **依赖方向约束**：`visp-fs` **不得**依赖 `visp-core` / `visp-config` / `visp-daemon` / `visp-codegraph`（领域类型留在消费端，契约只含「路径 + 事件类型」）。这是它必须独立成 crate 的理由：`visp-codegraph` 不依赖 `visp-config`，若放 `visp-config` 会给 codegraph 引入无关依赖；放 `visp-daemon` 会导致 codegraph 反向依赖 daemon（循环）；`visp-core` 语义混杂。
- 模块内部封装对 `notify` 的使用；迁移后 `visp-codegraph`、`visp-daemon` 移除对 `notify` 的直接依赖（已确认两者除此之外无其它用途）。

### 4.2 语义契约（本设计的核心）

消费者声明若干**监听目标**，每个目标 = `(根路径, 模式, 过滤规则)`，模式二选一：

- **递归**：根目录及其整个子树。
- **直接子级**：仅根目录的**直接子文件**（其中可能只有部分符合过滤规则）。

模块承诺：

| # | 保证 |
|---|---|
| **G1** | 匹配的**已存在文件**，其**通过常规写入路径（`write` / `truncate` / `rename`）产生的**内容修改，在**本模块支持的后端集合**上均上报事件 |
| **G2** | 对匹配文件的**创建、删除、重命名**上报事件 |
| **G3** | 事件以「路径 + 事件类型」的形式投递（类型见 §4.6 归一化表） |
| **G4** | **不**保证事件顺序、不保证合并、**不保证去重**——一次逻辑保存可能产生多个/多种事件，消费者自行防抖 |
| **G5** | **允许根路径不存在**：自动监听最近的存在祖先，根出现后自动挂载；并发出**「需要重新扫描」信号** |

**「本模块支持的后端集合」的定义**：当前为 workspace 特性锁定下的 `inotify`（Linux）/ `macos_kqueue`（macOS）/ `ReadDirectoryChangesW`（Windows）。**若移除 `macos_kqueue` 特性改用 FSEvents，契约范围需重新评估**（FSEvents 有聚合/延迟特性，事件粒度不同）。

**明确不承诺**（写入契约，避免隐式假设）：

| 不承诺项 | 说明 |
|---|---|
| mmap 写入 | inotify 明文不产生 `IN_MODIFY`（如某些数据库/内存映射写入） |
| 经监听目录之外路径的写入 | 如硬链接：经非监听路径写同一 inode 不产生事件 |
| **符号链接是否跟随** | notify 递归默认 `follow_links(true)`——**会**跟随 symlink 目录树，可能监听跟出根之外。本模块**沿用该默认**（跟随），并在此明示 |
| 大小写不敏感 | 匹配为字符串精确匹配；APFS 默认大小写不敏感下 `agents.md` 与 `AGENTS.md` 可能漏匹配 |
| 事件精确计数/时序 | 见 G4 |
| 跨进程一致性 | — |

**消费者义务**：事件与重扫信号均为**幂等输入**——消费者不得依赖计数、顺序或唯一性；收到事件/信号后应做全量或增量的幂等处理。

### 4.3 实现策略（默认策略；允许后端特化）

- **递归目标**：交由 notify 的递归能力。
  - kqueue 下它**为子树每个文件建 watch**（内容改写可感知）；
  - inotify 下它**只挂目录**，内容感知依赖**内核冒泡**；
  - Windows 下依赖 `LAST_WRITE`。
- **直接子级目标（默认策略）**：**目录监听负责结构性事件**（创建/删除/重命名），**同时对每个匹配的直接子文件单独挂文件级监听**负责内容修改。文件级监听在三类后端都会在内容写入时触发，因此这是**跨平台成立**的做法（在 inotify/Windows 上冗余但无害）。
- **文件级挂载必须幂等（P0 修正）**：对 Create / Rename 涉及的路径**无条件 `unwatch + watch` 重挂**；或维护 `(dev, inode)` 集合，**inode 变化即视为新文件**。**不得**采用「路径已在集合就跳过」的写法——原子替换（tmp+rename）会在**同一路径**上换成新 inode，跳过重挂会让新 inode 失去监听，使后续原地覆写再次漏检。
- **维护监听集合**：记录已挂载的目录与文件路径，用于停止时释放；**去重的目标是「不产生重复的监听状态」，而非「跳过必要的重挂」**。
- **缺目录降级**（承接 G5）：根不存在时监听最近存在祖先 + 过滤；目录被创建后补挂，并发出重扫信号。**校准为事件驱动、批次内收敛**。
- **运行中目录目标被删/重命名**：等价于「根不存在」——转入降级监听并保持可恢复（重新创建后自动补挂）。
- **平台特化**：模块内**优先不写 `cfg(target_os)`**；若某后端确需特化（如 Windows 文件级 watch 实为「监听父目录 + 按路径过滤」，其 unwatch 为引用计数语义；或未来启用 FSEvents 时的流模型），**适配点集中于本模块内**，契约仍只承诺 G1–G5 的**结果**。

### 4.4 目标声明与过滤规则（只述职责，不写签名）

- **目标声明**：表达 §4.2 的 `(根, 模式, 过滤规则)` 列表。
- **过滤规则**（支持现有两处消费者的最小集合，不做通用 glob 引擎）：
  - **包含**：文件名匹配、扩展名匹配、前缀/子树匹配。
  - **排除**（**P1-3 补全**）：路径组件级排除（codegraph 现有 `node_modules` / `.git` 需要）。
  - 注意扩展名**含点/不含点**两种书写习惯的兼容（codegraph 现状两种都用）。

### 4.5 接口职责（只述职责，不写签名）

- **启动/停止**：启动返回一个句柄；句柄 `stop` 后不再投递事件、释放全部监听。
- **事件投递**：向消费者提供的接收端投递事件；投递**不阻塞监听回调线程**。
- **重扫信号**：因缺目录补挂而发出（G5）；消费者幂等处理。
- **线程约定**：句柄与接收端应为 `Send`；接收端被 drop 后不 panic（静默停止投递或尽力投递）。
- **纯函数部分**（便于单测）：目标声明与路径匹配的**判定**、缺目录降级链的**解析**、事件类型**归一化**。

### 4.6 事件类型归一化（P1-2 新增）

事件类型集合：`创建` / `修改` / `删除` / `重命名`。

归一化约定：

| 底层情形 | 归一化结果 |
|---|---|
| 新建文件 | `创建` |
| 内容写入（write/truncate） | `修改` |
| 原子替换（tmp + rename 覆盖目标） | 目标路径的 `重命名`（并将临时文件的创建/删除按普通事件处理或抑制，由实现择一，**须在文档中固定**） |
| 删除 | `删除` |
| 重命名（原地改名） | `重命名`（携带旧路径或新路径，二者至少一者可推导） |

**消费端容错要求**（迁移 codegraph 时必须满足）：消费者对「删除已不存在的路径」「创建已存在的路径」「对同一路径的多次`修改`」必须**幂等**。codegraph 现实现把 `Modify`（含 `Rename`）一律归为「修改」并走增量 `update_file`——迁移后若归一化拆分了 rename，**其消费端行为会改变**（大概率更正确，但**不是行为等价迁移**），需专项回归。

### 4.7 迁移

- **`visp-daemon/src/watch.rs`**：保留其**领域分类**（路径 → rules/skills/agents）与 debounce 聚合；把「监听计划构建 + notify 挂载 + 缺目录补挂 + 去重」下沉到 `visp-fs`。daemon 侧改为声明现有 9 类目标（出处见旧文档 `docs/design/2026-09-24-reload-design.md` **§5.6 表格**）并消费事件。
  - 现有 8 个集成测试将被**结构性改写**（构造路径经 `visp-fs` 接口），断言语义尽量保持。
  - 注意：现有 `rapid_writes_are_debounced_into_one_reload` 用例此前**恰好掩蔽了覆写盲区**（多次写入丢事件但「1 次重载」断言仍成立）；改写时须把「**原地覆写必须产生事件**」显式断言化。
- **`visp-codegraph/src/watcher.rs`**：把「递归监听 project + 扩展名过滤 + exclude 目录」表达为一个递归目标 + 包含/排除过滤；索引器消费事件的部分按 §4.6 的容错要求调整。
  - **明确决策：codegraph 忽略 `visp-fs` 的重扫信号**（现状：project 不存在时仅 warn 且无监听，索引器本就无用；lazy 启动 + 全量 `build_full` 兜底不受影响）。
  - 回归重点：索引新鲜度（事件丢失 → 索引陈旧且无报错，故必须专项回归）。

### 4.8 可测试性

- 判定/降级链/归一化等纯逻辑：单测。
- 运行时：临时目录集成测试，**必须新增「已存在文件的原地内容覆写」与「原子替换后继续原地覆写」两个用例**（现有测试盲区 + P0 的直接验收）。
- 因测试运行在本机后端（macOS kqueue），断言一律用**有限时间轮询的最终收敛**，不依赖事件序列或精确次数。
- **Linux inotify 冒烟计划**：G1 宣称覆盖支持平台，验收不能只有 macOS；至少安排 Linux 环境（CI 或容器）跑同一组集成测试。

## 5. Part 2 — AGENTS.md 向上边界

### 5.1 规则

从项目目录向上遍历，逐层加载该层的 `AGENTS.md`（近的优先），**边界规则**：

1. 若某层目录含 `.git`（**目录或文件**，后者用于 git worktree / submodule）→ **处理完该层后停止**向上。
2. 若一路上未遇到 `.git` → **不向上越过 `$HOME`**（项目在 `$HOME` 之下时到 `$HOME` 为止）。
3. **项目不在 `$HOME` 之下（如 `/tmp/x`、`/opt/x`）→ 不向上**，只加载项目层自身的 `AGENTS.md`。
   > **P1-4 修正**：v1 曾写「到 `/` 为止」，那会让 `/tmp/AGENTS.md` 作用于 `/tmp` 下所有项目、在多用户主机上重新引入注入面，与本设计「消除跨项目泄漏」的动机自相矛盾。
4. 独立的「全局 AGENTS.md」（`~/.config/visp/AGENTS.md`）**保持不变**，与向上遍历是两条正交通道。

### 5.2 理由

- git 根即「项目边界」的通用直觉；monorepo 仍正确（git 根在子包之上）。
- 与「全局 AGENTS.md」通道不重叠，消除「离项目很远的祖先目录静默生效」的意外泄漏。
- 非 git 项目退化为「到家目录为止」，绝不越过可写公共目录。

### 5.3 影响点（必须一致）

- **加载器**：`visp-config/src/rules.rs` 的 `discover_agents_md`。
- **监听计划**：`visp-daemon/src/watch.rs` 的目标 #1（祖先链）——必须与加载器用**同一套**边界解析。
- **抽取**：把「**祖先链（目录列表）**解析」抽为 `visp-config` 内的**单一函数**，加载器在其上查「存在的 AGENTS.md」，监听计划在其上生成监听目标。现状两处逻辑确实一致（均为无界到 `/`），抽取可行。
- **时机差异（已知）**：监听计划在 daemon 启动时**快照**，加载器**每次重载重算**。运行中若发生 `git init` 等导致边界变化，可能出现「监视的层 ⊃ 加载的层」的分叉——**无害**（变化守卫兜底），但契约上以**加载器运行时语义为准**，监听为启动快照。

### 5.4 边界情况

| 场景 | 行为 |
|---|---|
| 项目即 git 根 | 只加载项目自身的 AGENTS.md |
| monorepo（项目是子目录） | 一路上溯至 git 根，沿途 AGENTS.md 全部加载 |
| 嵌套 git（submodule 内） | **最近的 `.git` 即边界** → submodule 内不加载父仓库的 AGENTS.md（submodule 视为独立项目，与 cargo/rust-analyzer 惯例一致） |
| git worktree（`.git` 是文件） | 同样视为边界 |
| 非 git 项目、位于 `$HOME` 之下 | 到 `$HOME` 为止 |
| 非 git 项目、位于 `$HOME` 之外 | **不向上**（P1-4 修正） |

## 7. 验收标准

### 7.1 `visp-fs` 契约
1. **内容改写可感知（非递归目标）**：临时目录中**创建后再原地覆写**其内容 → 收到「修改」事件（macOS kqueue 下必须通过；核心修复项）。
2. **原子替换后仍可感知**：对目标文件做 tmp+rename 原子替换 → **随后再原地覆写** → **仍收到「修改」事件**（P0 的直接验收；旧策略在此失败）。
3. **结构性事件**：创建/删除/重命名均上报，且符合 §4.6 归一化表。
4. **动态补挂**：目标目录不存在 → 运行中创建并写入 → 收到事件且触发一次重扫信号。
5. **监听状态收敛（替代 v1 含糊措辞）**：重复 create/delete 风暴下，**监听状态收敛正确、无句柄泄漏**（以监听集合大小/挂载次数断言）。
6. **停止清理**：`stop` 后不再投递、监听释放。

### 7.2 迁移与回归
7. **daemon 热重载**：原地覆写 `AGENTS.md` 现在能触发 rules 重载（本次缺陷的直接验收）。
8. **codegraph 索引器回归**：源文件原地覆写、原子替换、重命名、exclude 目录内变更、无关扩展名事件零触发 —— 索引新鲜度正确。
9. **Linux 冒烟**：同一组 §7.1 集成测试在 Linux（inotify）通过。
10. `cargo test --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo fmt -- --check` 全绿。

### 7.3 AGENTS.md 边界
11. **止于 git 根**：在 git 根之上人为放置 AGENTS.md → 不被加载、不被监听。
12. **monorepo 正确**：子目录项目仍加载至 monorepo 根的各层 AGENTS.md。
13. **非 git 项目**：`$HOME` 之下止于 `$HOME`；`$HOME` 之外**不向上**。
14. **加载器与监听计划一致**：同一祖先链解析被两处共用（无「监听但不加载」或反之）。
15. **rename 归一化单测**：§4.6 表中每一行都有单测。
